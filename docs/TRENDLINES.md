# خطوط روندِ اصولیِ پرایس‌اکشن (M10)

این سند منطقِ دقیقِ ماژول `modules/10_trendlines_pa.pine` را توضیح می‌دهد؛
همان منطقی که در `src/SMC_NTS_Pro.pine` (بخش M10) ادغام شده است.

## ۱. چرا این پیاده‌سازی «اصولی» است؟

سه خطای رایج در اسکریپت‌های خط‌روند که اینجا حذف شده‌اند:

| خطای رایج | رفتارِ این ماژول |
|---|---|
| استفاده از `highest()/lowest()` یا پیوتِ تاییدنشده → خط مدام جابه‌جا می‌شود (Repaint) | فقط پیوتِ **تاییدشده** (`ta.pivothigh/low`)؛ خط پس از ترسیم دیگر عقب‌گرد ندارد |
| وصل‌کردنِ هر دو نقطه به هم، بی‌توجه به جهتِ ساختار | خط نزولی فقط از **سقف‌های پایین‌تر** و خط صعودی فقط از **کف‌های بالاتر** ساخته می‌شود |
| ترسیمِ خط بدون معیارِ اعتبار | دو معیارِ کمّی: **تلورانسِ لمس** و **شرطِ هال (Hull)** |

## ۲. قواعدِ ترسیم (گام‌به‌گام)

### قاعدهٔ ۱ — سقف و کف
سقف/کف فقط با پیوتِ تاییدشده شناخته می‌شود:

```
tlPH = ta.pivothigh(high, tlPivotLeft, tlPivotRight)
tlPL = ta.pivotlow (low,  tlPivotLeft, tlPivotRight)
```

هر پیوت `tlPivotRight` کندل دیرتر تایید می‌شود؛ این تاخیر طبیعی است و
درواقع همان چیزی است که جلوی بازترسیم را می‌گیرد. نقطهٔ لنگر همیشه
**نوکِ سایه** است (`high` برای سقف، `low` برای کف).

### قاعدهٔ ۲ — جهتِ ساختار
* خط روند **نزولی** = اتصال دست‌کم **۲ سقف** که هر کدام **پایین‌تر** از قبلی است.
* خط روند **صعودی** = اتصال دست‌کم **۲ کف** که هر کدام **بالاتر** از قبلی است.

اگر سقف/کفِ جدید در خلافِ جهت باشد، خط فعلی کنار گذاشته می‌شود و شمارش از همان
نقطهٔ جدید آغاز می‌گردد (ساختار عوض شده است).

### قاعدهٔ ۳ — لمسِ معتبر (دو شرط هم‌زمان)
یک پیوتِ جدید زمانی «لمس» حساب می‌شود که:

1. در نوارِ تلورانسِ دورِ خط باشد:
   `|قیمتِ پیوت − مقدارِ خط| ≤ tlTolAtr × ATR`
2. **شرطِ هال (Hull):** خطِ کاندید (از اولین لمس تا این پیوت) از هیچ‌کدام از
   سقف‌های قبلی پایین‌تر (برای خط نزولی) یا از هیچ کفِ قبلی بالاتر (برای خط
   صعودی) عبور نکند. به زبان ساده: خط باید روی لبهٔ ساختار بخوابد، نه از وسط آن.

شرطِ دوم همان کاری است که یک تریدرِ پرایس‌اکشن با چشم انجام می‌دهد
(«این خط از آن سقف رد شده، پس غلط است»).

### قاعدهٔ ۴ — ابطال (شکست)
خط فقط وقتی باطل می‌شود که **منبعِ سنجش** از خط عبور کند:

* پیش‌فرض = **کلوز** (`tlTouchBasis = "کلوز"`)؛ یعنی سایه‌های نفوذی (Liquidity
  Sweep / Stop Hunt) خط را نمی‌شکنند.
* اگر «سایه (High/Low)» انتخاب شود، هر نفوذِ سایه شکست حساب می‌شود (سخت‌گیرانه‌تر).
* اندازهٔ عبور باید بیش از `tlBreakAtr × ATR` باشد تا نویز، شکستِ کاذب نسازد.

پس از شکست: خط به صورت نقطه‌چینِ خاکستری بایگانی می‌شود (دیگر امتداد نمی‌یابد)،
یک برچسبِ «شکست» ثبت می‌گردد و هشدار (BOS) صادر می‌شود.

### قاعدهٔ ۵ — پیش‌نویس در برابر تاییدشده
| تعداد لمس | نمایش | معنا |
|---|---|---|
| ۲ | خط‌چین، ضخامت ۱ | پیش‌نویس (حداقلِ درخواستی شما) |
| ۳ به بالا | خط پر، ضخامت ۲ | تاییدشده؛ معتبرتر برای معامله |

### قاعدهٔ ۶ — تمایز با ناحیهٔ روزانهٔ قبل (Previous Daily Premium / Discount)
سقف و کفِ روزِ قبل و سطحِ تعادل (Equilibrium) آن‌ها محاسبه می‌شود:

```
PDH = high[1]  در تایم‌فریم D
PDL = low[1]   در تایم‌فریم D
EQ  = (PDH + PDL) / 2
بالای EQ = پریمیوم  (منطقهٔ فروش)
زیر  EQ = دیسکانت  (منطقهٔ خرید)
```

ناحیه دقیقاً در **کندلِ خودِ پیوت** سنجیده می‌شود (نه کندلِ جاری)، برای این کار
از دسترسی به تاریخچه با اندیسِ ثابت استفاده شده است:

```
tlPdEqBar   = tlPdEq[tlPivotRight]
tlPdPremBar = close[tlPivotRight] > tlPdEqBar
```

سپس بر اساس انتخابِ `tlPdMode`:

* **بدون فیلتر** — ناحیه فقط نمایش داده می‌شود.
* **تاکید روی همسو** (پیش‌فرض) — خطی که لمس‌هایش در ناحیهٔ درست شکل گرفته
  (مقاومت در پریمیوم / حمایت در دیسکانت) با رنگِ پررنگ و خطی که همسو نیست با
  رنگِ محو کشیده می‌شود.
* **فقط همسو** — لمس‌های ناهمسو اصلاً شمارش نمی‌شوند (سخت‌گیرانه؛ پیشنهاد نمی‌شود
  مگر برای فیلترِ دستی).

## ۳. خروجی‌های قابل استفاده در بقیهٔ اندیکاتور

| خروجی | نوع | توضیح |
|---|---|---|
| `tlDnLive` / `tlUpLive` | bool | آیا خطِ فعالی وجود دارد |
| `tlDnHits` / `tlUpHits` | int | تعداد لمس‌های معتبر |
| `tlDnYNow` / `tlUpYNow` | float | قیمتِ لحظه‌ایِ خط (برای فاصله/سیگنال) |
| `tlDnBreakNow` / `tlUpBreakNow` | bool | رویدادِ شکست (یک کندل) |
| `tlAtSupport` / `tlAtResistance` | bool | قیمت به خطِ فعال نزدیک است |
| `pdInPremium` / `pdInDiscount` | bool | موقعیتِ قیمت نسبت به تعادلِ روزِ قبل |

در فایل مرجع، `tlAtSupport` به امتیازِ خرید و `tlAtResistance` به امتیازِ فروش
اضافه شده است (مقدارش با ورودیِ `tlBonus` کنترل می‌شود؛ برای غیرفعال‌کردن، ۰ بگذارید).

## ۴. هشدارها (Alerts)

* شکستِ خط روند نزولی = BOS صعودی
* شکستِ خط روند صعودی = BOS نزولی
* لمسِ جدید روی خط روند نزولی / صعودی

## ۵. پیشنهاد تنظیم

| تایم‌فریم | `tlPivotLeft` | `tlPivotRight` | `tlTolAtr` |
|---|---|---|---|
| ۵–۱۵ دقیقه | ۴ | ۲ | ۰.۳۰ |
| ۱ ساعت | ۵ | ۳ | ۰.۳۵ |
| ۴ ساعت / روزانه | ۷ | ۳ | ۰.۴۰ |

هرچه `tlTolAtr` بزرگ‌تر باشد لمس‌های بیشتری پذیرفته می‌شود (خطوطِ بیشتر ولی
کم‌دقت‌تر). هرچه کوچک‌تر باشد، فقط خطوطِ واقعاً تمیز کشیده می‌شوند.

`tlReanchor` (پیش‌فرض: روشن) وقتی ساختار از خط سبقت گرفت، خط را روی دو
سقف/کفِ آخر بازترسیم می‌کند — همان کاری که یک تریدر روی چارت انجام می‌دهد.
اگر خطِ قدیمی تاییدشده (۳ لمس به بالا) بود، ابتدا بایگانی می‌شود تا روی چارت بماند.

## ۶. تستِ منطق بدون تریدینگ‌ویو

```bash
python3 tools/sim_trendlines.py            # خروجی: tools/sample_trendlines.png
```

این اسکریپت همان الگوریتم را روی دادهٔ مصنوعی (کانال نزولی + کانال صعودی + شکست)
اجرا می‌کند: خط‌چین = ۲ لمس، خط پر = ۳ لمس به بالا، خاکستری نقطه‌چین = خط شکسته.

## ۷. محدودیت‌ها

* کامپایلر رسمی تریدینگ‌ویو در این محیط در دسترس نیست؛ فایل با
  `tools/check_pine.py` از نظر نحو/کاراکترهای نامرعی بررسی شده، اما تایید نهایی
  با یک بار **Add to chart** انجام شود.
* تعداد اشیاء: `max_lines_count=500`, `max_labels_count=500` لازم است.
* فضای بایگانی با `tlMaxLines` (پیش‌فرض ۱۲ خط برای هر جهت) و برچسب‌ها تا ۶۰ مورد
  محدود شده‌اند تا از خطای «Too many drawings» جلوگیری شود.
